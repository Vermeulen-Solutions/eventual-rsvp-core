# Eventual RSVP – Core 0.18.5 — links on Registry installs

- **Subscribe links work on Registry installs.** A plugin installed from the EmDash Registry is addressed by a generated ID that starts with `r_`, not by `eventual`. The **Subscribe** links on the Eventual RSVP admin page (calendar subscription and JSON feed) still used `eventual` and answered "Plugin route not found" on those sites. They now use the installed ID, so they also show a site builder the exact addresses to use. ([#7](https://github.com/Vermeulen-Solutions/eventual-rsvp-core/issues/7))
- **Per-event `.ics` links too.** The `calendarLinks.ics` address that the public feed gives for each event had the same fault. Pages that render it (for example `EventList.astro` with `showCalendarLinks`) get a working link after the update, without a code change.
- **The per-event `.ics` link downloads that event only.** It used to return the whole year's calendar, because the `calendar` route ignored `eventId`. Now `calendar?eventId=<id>` returns one event: every upcoming date of a repeating event, or one date with an occurrence ID (`<id>#<date>`). The link from a translated page gives that translation. The event keeps the UID it has in the subscription, so subscribers do not get a duplicate. An unknown, unpublished or past event answers 404. The subscription itself is unchanged.
- **Helpers on npm:** `buildCalendarLinks(event, siteUrl, pluginId)` takes the plugin ID as an optional third argument. The Astro showcase reads it from the new optional `EVENTUAL_PLUGIN_ID` setting.
- **Clearer documentation** ([#8](https://github.com/Vermeulen-Solutions/eventual-rsvp-core/issues/8)): the [developer guide](developer-guide.md) has a new file name and starts with versions and where to get them. It warns against the unrelated npm package `eventual`, explains what goes wrong with two backends on one site, and says where to turn on agent tools.
- **Nothing else changes**: no permission or schema changes, and no new MCP tools. Config-managed installs keep the ID `eventual` and behave exactly as 0.18.4. EmDash `>=1.2.0 <2.0.0` (tested on 1.2.0, 1.4.0 and 1.5.0).
